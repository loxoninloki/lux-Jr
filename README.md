# LUX NEXT

ろき様のためのAI相棒。React / TypeScript / Vite + GitHub Pages の静的PWAです。既存の `lux-app` と独立しています。

## 状態（2026-11-05）

- 実装: 会話UI、ローカル履歴、明示的な記憶の追加・編集・削除・検索、JSONエクスポート・初期化、Web Speech音声入力・読み上げ、画面が開いている間の予定・毎日/毎週の繰り返し・タイマー・通知履歴、PWAマニフェスト・Service Worker。
- 実装・単体テスト済み、未デプロイ: Cloudflare Worker + SQLite Durable Objectによる認証、入力検証、サーバー側予算制限、6回/分の制限、503の最大3試行、429の停止、タイムアウト、Gemini接続処理。
- 未検証: 実Gemini応答、Cloudflare実環境、iPhoneの音声認識・音声再生・ホーム画面インストール・オフライン挙動。
- 未実装: 閉じた状態でのWeb Push、サーバースケジューラー、会話からの予定自動登録、ハンズフリー・割り込み、クラウド同期、ローカル暗号化、課金、アカウント登録。

AI未接続時に架空のAI回答は表示しません。設定が必要であることを表示します。

## 開発 / 公開

Node.js 22.12以上。`npm install` → `npm test` → `npm run build`。GitHub Actionsは `main` へのpush後に検証・ビルドし、`dist` のみをPagesへ公開します。ソースやWorker設定はPagesの配信ファイルに含めません。

GitHub Settings → Pages → Sourceを **GitHub Actions** に設定。ベースURLは `/lux-next/` です。アプリの名前を変える場合はVite、マニフェスト、SWのscopeを揃えて変更してください。

## 安全なAI接続（設定が必要）

1. Cloudflareへログインし、Workers & PagesでGitHubのこのリポジトリを接続。Workerとして `wrangler.jsonc` を使用し、ビルド不要、デプロイコマンド `npx wrangler deploy` で配置します。ローカルなら同じコマンドを利用できます。
2. Workerの設定に、以下を **Secret** として追加します。GitHub・このREADME・ChatGPTの本文には貼り付けないでください。
   - `GEMINI_API_KEY`: Google AI Studioで作成したAPIキー。
   - `ACCESS_TOKEN`: パスワードマネージャー等で生成した32文字以上のランダムな専用コード。Gemini APIキーとは別物です。
3. `BUDGET` のDurable ObjectバインドとSQLite migrationが適用されていることを確認。未設定ではリクエストを拒否します。
4. アプリ「設定」にWorker URLと **専用アクセスコード** を入力し、「接続を確認」。コードはブラウザのメモリ上だけに保持し、閉じると消えます。APIキーは入力しません。
5. 少量の実リクエストでモデル利用権限・API無料枠・単価をGoogle AI Studioで確認。

### 予算とモデル

初期モデル `gemini-3.5-flash-lite`。公式単価は100万トークンあたり入力$0.30、出力$2.50（2026-11-05確認）。無料枠の実際の上限はプロジェクトごとにAI Studioで確認してください。無料枠では入力がサービス改善に使われる場合があります。

Workerの `MONTHLY_BUDGET_YEN` は初期1000、最大2000。`USD_JPY` は概算用の設定値150で、現在為替を示すものではありません。請求通貨・税・為替差・単価改定を含む実際の支払額の保証ではありません。

予算判定はブラウザ値を信用せず、DOに保持したJST月別予約台帳で行います。最大3試行分のトークン上界見積もり（入力UTF-8バイト数+余裕、出力2048）を送信前に予約し、失敗しても解放しません。実利用の概算と予約額を分けて表示します。安全側なので実費より早く上限に達します。キーをこのWorker以外で使った料金は制御できません。単価変更時には `price()` を更新してください。現在は初期モデルだけを許可し、高額モデルへの任意変更を拒否します。将来のモデル追加は検証・単価追加を伴うサーバー変更で行います。

サーバーは会話本文や記憶を永続保存せず、本文ログ出力も行いません。Cloudflare/Googleのサービス側の処理・保持は各社の規約に従います。トークン認証は一人用であり、将来の一般提供前にはユーザー認証・ユーザー別台帳・データ分離への変更が必要です。

## データと音声の注意点

- 保存はブラウザlocalStorage。暗号化ではなく、端末の共有や同一originの別アプリからのアクセスにも注意が必要です。GitHub Pagesでは同じ `loxoninloki.github.io` の他のページとoriginを共有します。他人が別端末から同じURLを開いても、この端末の会話は取得できません。
- 記憶の保存は本人による手動操作のみ。機微情報を自動抽出しません。Gemini送信時は直近16メッセージと登録記憶を文脈に使用します。
- エクスポートは平文JSONなので安全に保管してください。Safariのサイトデータ削除や容量整理で保存内容を失うことがあります。
- 音声認識は端末/ブラウザが提供し、提供元へ音声が送られる場合があります。声の性別・品質や自動再生は端末依存です。読み上げボタンと停止ボタンを用意しています。
- オーブの音声連動は認識中/読み上げ中の**状態**への連動です。マイク音量に比例する可視化ではありません。
- iOS 16.4以降ではホーム画面に追加したWebアプリでWeb Pushが使えますが、本人操作による許可、Push購読、サーバー側配送・スケジューラーが必要です。この版はWeb Pushを実装していません。タイマーは画面を開いている間に確認し、バックグラウンドの正確な時刻を保証しません。

## ボタン式の音声会話（2026-11-05追加）

会話画面の「音声会話を開始」から、日本語認識→認識終了後に自動送信→返答の読み上げ→650ms待って次の聞き取りを行います。一般の自動読み上げ設定がオフでも、このモードは音声で返答します。通常のテキスト・マイク入力も残しています。

終了・画面の非表示・他画面への移動で認識と読み上げを停止し、進行中のfetchを中断します。遅れて届いた認識結果やAPI応答から再開しないようセッションを識別します。サーバーへ届いた処理のキャンセル・料金取り消しを保証するものではありません。認識エラー・無音・API制限時は自動再試行ループを作らず終了し、再開を案内します。

再生が拒否された場合はマイクを再開せず「返答を再生して続ける」で本人の操作を待ちます。読み上げの終了を確認してから聞き取りに戻します。読み上げ開始10秒・終了最大5分、認識60秒・停止確認4秒の監視があります。

- 自動テスト済み：二重結果の一回送信、マイク停止待ち、読み上げ完了待ち、停止後の遅延イベント無視、APIの中断、再生拒否時の本人操作による再開、認識拒否・無音・429による終了、古いセッションの無効化。
- 未検証：iPhone Safari実機での音声認識・自動再生・複数ターンの安定性。
- 未実装：発話中の割り込み、双方向ストリーミング、画面を閉じた状態の継続会話。この機能はGemini Live APIではなく既存テキストAPIと端末音声の順番式です。

実機確認：接続設定→「音声会話を開始」→許可→短く話す→自動で返信が読み上げられる→再び話す。送信待ち中・読み上げ中に「終了」を押して再開しないことも確認してください。自動再生が止まった場合は表示された再生ボタンを押します。

API仕様参考：<https://wicg.github.io/speech-api/>、<https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/end_event>、<https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/end_event>


### 返答後のマイク復帰対策（2026-11-05）

前版の650ms待機・start呼び出しだけの復帰処理を更新しました。認識終了後にイベントハンドラを外してabortで旧マイク処理を解放し、音声再生終了後はキューを解除、1,200ms待って新しい認識器を起動します。startイベントの確認前は「起動中」と表示します。

8秒間開始通知がない場合、25秒間結果が来ない場合、無音・一時的な認識エラーは、マイクだけ最大2回再接続します。これは発話がない状態とSafariの認識停止を完全には区別できないための復帰策です。再接続だけでGeminiへ再送しません。復帰失敗はモードを保持して「マイクを再開」を案内。聞き取り中も同ボタンを押せます。終了後の古いイベント・再接続待ちは無効になります。

音声会話のリクエストにはvoiceMode=trueを付け、Workerで読み上げ向けの短い自然な返答を指示します。通常の文字会話の読み上げ設定は変更しません。モード中は「ルクスの音声応答 ON」を表示。キャラクターの上下・左右の揺れと傾きを少し拡大し、動きを減らすOS設定は引き続き尊重します。

自動テスト24件で、旧マイク解放、開始通知待ち、無反応時の再接続・回数上限、手動復帰、停止後の再開防止、音声モード指示を確認。Safari実機での症状改善は未確認です。WebKitの類似報告：<https://bugs.webkit.org/show_bug.cgi?id=321436>。回避策はOSバージョンにより有効とは限らず、今回の端末で同じ原因と断定していません。

読み上げ完了通知が欠ける場合にも対応：再生が始まったことを確認した後、再生中・待機中・一時停止中のいずれでもない状態が900ms続いた場合に完了を補完します。読み上げの推定時間では完了扱いしません。終了通知だけが届き開始通知が欠ける場合も完了として扱います。27件の自動テストに、通知欠落・キュー待機・一時停止・開始拒否を追加しています。

## 固定キャラクター画面・アクセスコード保存（2026-11-05）

会話画面は縦の画面内に収め、上段のLUXと下段の操作欄を固定。中央の履歴領域だけをスクロールします。全履歴を保持し、直近の一往復程度を見ながら過去へ戻れます。過去を閲覧しているときは新着で強制的に最下部へ動かさず、本人が新規送信すると最新へ戻ります。小さい画面やソフトキーボード表示時はキャラクターのサイズを縮小します。

アクセスコードは初期状態では保存しません。設定の「この端末にアクセスコードを保存」をオンにした場合のみ、別キーのlocalStorageに保存し、次回起動時に読み込んで接続を確認します。オフまたは全データ初期化で保存分を削除します。端末上の保存は暗号化された保管庫ではありません。専用の端末で本人が選択する設定です。Gemini APIキーは引き続きWorkerだけに保存します。アクセスコードは履歴JSONのエクスポートに含めません。

音声認識の確定結果があるのにend通知が来ない場合、従来は再接続で結果が失われていました。4秒後にマイクを解放してその結果を1回だけ送信するよう変更。「話し終わり」を押した場合は本人の操作により途中の認識文字も送信できます。途中文字を操作なしで確定扱いにしません。終了ボタンで遅延送信を防ぐテストも追加しました。

設定の「音声の動作状況」には状態遷移だけを直近40件表示し、本人操作でコピーできます。会話本文・アクセスコード・APIキーを記録せず、サーバーにも送りません。実機の音声問題の原因は断定せず、この状態表示を使って調査を継続できます。自動テスト33件、iPhoneの継続会話と画面レイアウトは実機確認待ちです。

## Gemini Live 無料枠試験（2026-11-05）

通常の認識→テキストAPI→端末読み上げのループとは別に、`gemini-3.8-live` へのネイティブ音声の双方向WebSocket接続を追加。標準音声エンジンはLive、従来方式は設定から選択できます。Google公式料金表ではこのモデルに入出力無料の枠があることを確認しました。ただしキーのプロジェクトが現在無料プランかをアプリから照会する機能はありません。本人がAI Studioで確認し、設定の確認欄をオンにしてから開始します。Google側の課金プラン変更・支払方法追加・有料モデルへのフォールバックは実装していません。課金済みプロジェクトのキーなら同じモデルでも料金が発生し得るため、アプリの「無料枠試験」という表示だけで課金されないことを保証するものではありません。

- `POST /live-ticket`：既存Bearer認証、入力サイズ検証、固定モデル、一回だけ使える20秒の接続券を発行。コード/APIキーをブラウザのWebSocket URLに入れません。Worker→Google間だけでAPIキーを使用します。
- `/live`：接続元を厳密検証し、DOの接続券を取引内で消費してからGoogleへ接続。設定・システム人格をサーバーで固定し、クライアントからは16kHzのPCM音声だけを許可。音声送信量も実時間に応じて制限します。本文・キーはログ出力しません。
- サーバー側の試用制限：1回120秒、1回最大12往復。日次の回数上限は撤廃しました。Googleの無料枠の残量を示すものではありません。自動で再接続/再課金する処理はありません。
- 既存の月間アプリ予算も維持。1開始につき予算判定用の100円を安全側に確保（請求額ではありません）。未使用/失敗分も解放しません。Liveは通常チャットのトークン集計と別で、通常チャット残り回数の計算ではLive確保分を差し引きます。料金改定やキーの他用途での利用を含む請求総額を保証する仕組みではありません。
- ブラウザ：AudioWorkletで16kHz PCM16へ変換、マイクを開いたまま24kHz応答をWeb Audioで順次再生。Googleのinterruptedイベントで未再生音声も停止。声はKore。画面非表示・終了・通信エラーではトラック、AudioContext、両側ソケットを閉じます。
- 会話文字起こしは入力/出力を履歴へ保存。長期記憶と直近会話を開始時に参考情報として渡します。録音ファイルは保存しません。音声はCloudflare経由でGoogleへ送信され、無料API枠のデータ利用条件が適用されます。

自動テスト41件（PCMの符号・サンプルレート、マイクのローカル音声出力禁止、固定モデル、送信形式の制限、接続券の再利用防止、同時起動/日次/月次制限、120秒での両ソケット停止、割り込み後もマイクを維持し音声を止める挙動等）。実Gemini Live接続・iPhone Safariでのマイク/再生/割り込み/遅延・無料プロジェクトでのモデル利用権限は未検証です。

公式資料：<https://ai.google.dev/gemini-api/docs/pricing>、<https://aistudio.google.com/docs/live-api/get-started-websocket>、<https://aistudio.google.com/api-reference/live>、<https://developers.cloudflare.com/workers/examples/websockets/>。

## Live起動・音声の確認改善（2026-11-05）

利用者から音声認識・返答音声が動かないとの報告あり。実機の原因は未確定です。マイク許可後の音声ルーティング変更に備え、入力グラフを接続した後にAudioContextを再開します。Safariが音声を停止した場合は「音声を有効にする」の本人操作で同じ接続を再開します。音声処理モジュールはインラインURLではなく独立したJSファイルとして配信します。

実際のマイクフレームを確認するまでLive接続券を発行しません。マイク無反応10秒、処理モジュールのロード失敗、プロセッサ停止は明示的に表示します。接続準備中と開始完了を区別し、マイクの音量・音声送信数・返答音声受信数を表示。会話本文やキーは状態記録に含めません。Googleのエラー本文は転送せず、安全なエラー番号のみを表示します。

LIVE終了ボタンが従来エンジンだけを停止していた不具合を修正しました。ルクスの下の待機挨拶は「おかえりなさい、ろき様。」に変更しました。自動テスト43件で中断後の音声再開・準備停止・遅延フレーム無視などを確認。実Gemini Liveとの送受信、iPhoneのマイク・スピーカー動作は引き続き実機確認が必要です。


## 接続前のマイク準備停止への対策

利用者の確認により、LIVEはGemini接続前のマイク・音声処理準備で止まっていることが分かりました。特定のSafari不具合とはまだ断定していません。AudioWorkletの読み込みが3秒で終わらない、または入力フレームが来ない場合、ローカルのScriptProcessor互換処理へ切り替えます。後者は非推奨APIであり将来の互換性を保証しませんが、標準方式を起動できない環境の予備としてのみ使います。APIキー・録音ファイルの保存・別AIへの接続は追加しません。マイク許可の待機も20秒で打ち切り、後から許可された古いトラックは解放します。対応するSafariではAudioSessionをplay-and-recordにし、終了時に元へ戻します。

通常のマイクボタンは専用Dictation処理へ変更。start通知前は「起動中」、認識途中の文字も入力欄へ表示し、終了通知欠落時も確定します。入力するだけで、勝手にAIへ送信しません。起動拒否・通信失敗・起動通知欠落を分けて表示します。呼び方は画面・システム指示で「ろき様」に統一し、以前の会話も表示・読み上げ時に同じ表記にします（保存済み原文は保持）。49件の自動テストを通過。実iPhoneでの解消は未確認です。


## 日次試用回数の撤廃・診断保存

本人の依頼によりLUX独自の1日3回制限を撤廃。既存台帳に3回以上の記録があっても、回数を理由に拒否しません。1回120秒・12往復・同時接続防止・サーバー側月間予算と100円の安全側予約は維持します。従って回数が無制限でも、月間予算やGoogleの利用制限では停止します。Googleの課金設定は変更しません。早期終了時も前の接続枠の期限（開始券発行から最大140秒）までは次の接続を待つ場合があります。

音声の状態記録は直近100件を別のlocalStorageへイベント発生時に保存し、再起動後も表示します。日付・定義済み状態コードのみを許可し、会話本文・秘密情報は保存しません。入力音声の最初の送信・返答音声の最初の受信・開始前後の終了を区別。ストレージ保存不可・サイトデータ削除・全データ初期化による消失は防げません。Googleの無料枠残量やiPhone実機でのLive成功は依然未確認です。

## 従来音声の再認識診断・AIを使わない端末テスト

「声を試す」は聞こえる一方、読み上げ後の2回目はstartだけでresultが来ない実機報告を受けた追加対策です。Safariの類似報告は https://bugs.webkit.org/show_bug.cgi?id=321436 にありますが、この端末の原因・解消を確認したものではありません。

- 設定→「端末音声テスト（AI利用なし）」は既存の従来音声処理を使い、認識後に固定文「聞き取れました。もう一度、お話しください。」を読み上げます。チャットAPI・Live接続券・履歴保存は呼びません。予算や利用回数を消費せずに2回目以降を試せます。ただし端末の音声認識サービスは利用します。
- 読み上げ後の認識開始から10秒間resultがない場合、無音とSafariの不具合は区別できないため「認識結果が届きません」と表示してマイクを解放します。自動でAIへ再送したり、無反応の再起動を繰り返したりしません。「マイクを再開」の手動操作は残します。改善しない場合は音声会話を終了してページを開き直します。
- 読み上げキューがpausedの場合は、今回要求された読み上げの前にresumeを試します。再生待ち・開始イベント・状態からの開始検出・終了イベント・終了推定・タイムアウト・安全なエラーコードをspeech:*で記録します。再生イベントは、実際に聞こえたことの証明ではありません。
- recognition:audio-start / speech-start / audio-end / no-results / manual-restart / error-*を追加。音声・本文・生の例外は記録しません。保存キーと100件上限は維持します。

確認手順（Safari本体とPWA）: 設定で「声を試す」→「端末音声テスト（AI利用なし）」→一言話す→固定文が聞こえるか確認→二度目も話す→文字が表示されるか確認。無反応時は10秒後の表示と診断をコピーします。2回目の認識が直ったとは未検証です。通常のAI音声会話テストはこの端末テストが通ってから行ってください。

### 応答待ち時間と返答の長さの比較

端末音声テストに待ち時間なし・3秒（初期値）・10秒・30秒の選択と「長い返答」を追加しました。通常会話と同じbusy表示・送信中ガードを使い、AIへの接続、予算台帳、会話履歴への書き込みは使いません。停止やページ非表示で待機を中断し、古い返答から読み上げを開始しません。比較条件はrecognition:test-wait-*とtest-reply-short/longとして記録します。

まず3秒・短い返答で3往復、次に10秒・長い返答で3往復を確認します。必要に応じて待ち時間なしと比較します。これは通信待ち時間とUI状態を模したテストで、ネットワーク通信・実際のAI生成・履歴更新を再現するものではありません。自動テスト70件成功。Safariの不具合解消や本番会話の成功は未確認です。予算上限は変更していません。

### 待ち時間後の再生開始失敗とボタン再生

実機ログで、3秒待機後にspeech:queued→10秒後にspeech:start-timeout、その後の本人の再生操作では11ms後にspeech:start-event、最後にspeech:end-eventが届く試行を確認しました。この試行では操作直後なら再生できますが、ブラウザ内部の原因を断定したものではありません。再生終了後の再認識を開始する前にidleとなっているため、この試行だけでは二度目の認識の成否は分かりません。

自動再生開始のタイムアウトまたはnot-allowedを検出した場合、このページの従来会話・端末テストは以降ボタン再生へ切り替えます。次の返答を毎回10秒失敗させず、届いた時点で再生操作を案内します。設定の「返答をボタンで再生」から最初から選ぶこともできます。この設定は保存データを変更せず、ページを再読み込みするとオフに戻ります。音声ハードウェア等の別のエラーでは自動で切り替えません。

返答のテキストを保持して再生し、AIへ再送しません。再生開始はボタンの同期処理内で呼び出し、途中にネットワークや待機処理を入れません。再生完了まではマイクを再開せず、停止後の古いコールバックも無効にします。自動会話の完全なハンズフリーを解決する変更ではなく、ログで成功した本人操作による復旧を次の返答にも使う回避策です。Liveや月間予算は変更しません。

確認はAI利用なしの端末テストで3秒・短い文、ボタン再生オンにして3往復。毎回ボタンを押すと返答が聞こえ、その後も認識文字が出るかを確認します。実機の継続安定性は未検証です。
